Quick start

$cd cab-booking-saas
$make up
$make seed

Beginner guide

Read this and you are a professional

The whole product in plain language. Open any term you've ever nodded along to without fully knowing.

Multi-tenant SaaS — one deployment, many companies
A tenant is a customer workspace: its own users, cabs, drivers, customers, and settings. CabDesk runs one copy of the software for all of them. The hard part isn't sharing a server; it's making sure tenant A can never see tenant B's data. That's solved below the application code — see RLS.
Row-Level Security (RLS) — the database itself enforces isolation
Postgres lets you attach a rule to a table: rows are only visible when tenant_id matches the current tenant. CabDesk forces this on every tenant table, so even a buggy future query returns nothing rather than someone else's bookings. Fail-closed: if the tenant setting is missing, the answer is zero rows — never all rows.
Authentication vs. authorization — who you are vs. what you may do
Authentication proves identity (login). Authorization decides permissions (roles). CabDesk has five roles — owner, admin, manager, viewer, driver — and re-checks permissions in the API on every single request. Hiding a button is not security.
JWT & refresh token rotation — sessions that fight back
At login you receive a short-lived signed token (20 minutes). A longer-lived refresh token gets you new ones. Refresh tokens are stored hashed, rotated on every use, and if an old one is ever replayed, the whole family is revoked automatically — that's theft detection, the same idea serious banks use.
Docker & Compose — one command instead of a setup manual
Each part of the system (Postgres, Redis, API, web app, Caddy) runs in a container: a sealed box with everything it needs. docker-compose.yml declares all five, how they connect, and their health checks. make up turns that file into a running platform.
Migrations — version control for your database structure
A migration is a numbered, repeatable change to the database schema (create a table, add a column, install a security policy). Alembic applies them in order on startup, so every environment — yours, the demo, production — has the same structure, every time.
Feature flags & entitlements — how SaaS pricing really works
Each workspace carries a plan: reports, max_cabs, max_users, api_access, custom_domain. The server enforces them. Hit a limit and you get a clear refusal — "Cab limit (5) reached for your plan." — not a silent failure or corrupted data.
PWA — an app without an app store
A Progressive Web App is a website with a manifest, an icon, and a service worker. Open it on a phone and "Add to Home Screen" gives you a full-screen app with its own icon. No store review, no separate codebase.
Reverse proxy & automatic HTTPS — Caddy's job
Caddy is the front door. It receives traffic on ports 80/443, sends /api/* to the FastAPI backend and everything else to the Next.js frontend, and in production obtains and renews TLS certificates automatically. One less thing to remember at 2 a.m.
Health checks, seeding & tests — the boring words that keep it alive
Health checks prove each container is ready before traffic arrives. Seeding fills a fresh database with realistic demo data. Tests (22 of them) prove the rules hold — including deliberately nasty attempts to write across tenants, which fail exactly as they should.
